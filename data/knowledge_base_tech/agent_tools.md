# Agent 工具调用 / Function Calling

工具（Tool）是把聊天机器人升级为 Agent 的那条分界线。接入工具后，LLM 可以搜索网页、查数据库、发邮件、跑代码。

## 关键分离：决策 vs 执行

- LLM 负责决策：选哪个工具、传什么参数（生成一个结构化的调用请求，通常是 JSON）
- 执行器负责动手：跑函数、处理鉴权、管理限流、返回结果

LLM 本身不直接执行操作，也从不直接接触 API 密钥或凭证。结果再回传给 LLM，进入下一步推理。

## Function Calling 流程

1. LLM 接收用户指令
2. LLM 在内部推理，决定调用哪个工具 + 参数（生成 JSON 调用请求）
3. 执行器执行工具，返回结果（Observation）
4. LLM 根据结果重新规划下一步，或判断任务完成、结束循环

## 工具描述的重要性

系统提示里的工具描述 = 写给 LLM 看的「清单」。描述写得好，选择才准——垃圾描述进，垃圾调用出。

写工具描述时要想象一个聪明但较真的新手在读，讲清楚四点：

- 工具做什么
- 什么场景该用
- 返回什么
- 什么时候不该用

## 工具调用是潜在故障点

每一次工具调用都可能失败：超时、鉴权失败、返回格式异常，都可能中断整个流程。因此需要健壮的错误处理、重试与降级。

## CoT 与工具调用的关系

CoT 和工具调用不是互斥，而是协同。CoT 是让工具调用正确发生的「引擎」——LLM 在输出 JSON 调用请求之前，先在内部思考「用户要什么、该调哪个工具、传什么参数」。先想清楚（CoT），再动手（工具调用）。ReAct 就是把这两步串成循环。

## 工具相关的协议

- Function Calling：OpenAI 等模型的原生工具调用能力，LLM 返回结构化调用请求
- MCP（Model Context Protocol）：Anthropic 提出的规范接口，让外部工具统一方式与 LLM 交互
