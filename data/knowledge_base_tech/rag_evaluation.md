# RAG 评估指标

RAG 的质量取决于「检索」和「生成」两个环节，必须分开评估，才能定位问题出在哪一环——是没检索到，还是生成了但没用好检索结果。

## 检索指标

- Recall@k：相关文档出现在前 k 个检索结果中的比例，衡量「找没找得到」
- MRR（平均倒数排名）：首个相关文档排名的倒数平均，奖励「相关文档排得靠前」
- MAP（平均准确率）：评估所有相关文档的排序质量
- Context Precision / Recall：检索上下文中相关信息的精确率与召回率

## 生成指标

- Faithfulness（忠实度）：答案是否真正基于检索文档，有无凭空编造（幻觉率）
- Answer Relevancy（答案相关性）：答案是否紧扣用户问题
- Groundedness（基于性）：答案在多大程度上被提供的上下文支持

## RAG 三元组

LlamaIndex 和 TruLens 提出的经典三指标，分别对应「检索好不好、答案是否基于证据、答案是否扣题」：

1. Context Relevance —— 检索内容与问题的相关性
2. Groundedness —— 答案被检索上下文支持的程度
3. Answer Relevance —— 答案与问题的相关性

## 评估工具

- RAGAS：自动化 RAG 评估框架，内置上述指标
- TruLens：LlamaIndex 生态的评估工具
- LangSmith：LangChain 的评估与运行监控

## 评估流程

```
构建测试集（问题 + 标准答案 + 相关文档 ground truth）
  → 分阶段评估
     ├─ 检索：Recall@5 > 0.8 ?
     │    └─ 否 → 优化向量模型 / 分块 / 重排序
     └─ 生成：Faithfulness > 0.9 ?
          └─ 否 → 优化提示词 / 加引用 / 微调
  → 端到端测试
  → 上线监控，持续收集反馈
```

关键认知：检索是信息入口，检索质量几乎决定最终输出的上限。检索不到正确文档，生成器再强也无法「无中生有」。
