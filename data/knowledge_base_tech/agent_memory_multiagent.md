# Agent 记忆与多 Agent 架构

大模型有限的上下文窗口决定了不能把所有历史都塞进 prompt。设计高效的记忆机制，是 Agent 从「单轮问答」走向「长期协作」的关键。

## Agent 记忆的分类

- 短期记忆：当前对话的上下文（工作记忆），对话结束即失
- 长期记忆：跨会话沉淀的知识，存外部向量库，可随时检索召回
- 情景记忆：过往互动记录，面对相似任务时回看历史提升回答相关性
- 共识记忆：多 Agent 协作时共享的知识 / 技能库

## 记忆 vs RAG 的区别

- RAG：静态的知识外挂，从共享知识库检索事实，知识本身很少随交互改变
- Agent 记忆：动态生长，随着每次交互记录新经验、修正错误认知、遗忘不重要信息

两者互补：RAG 提供「世界知识」，记忆提供「用户理解」。少了 RAG 回答不够专业，少了记忆则不够个性化。

## 记忆的实现

长期记忆通常用向量数据库 + 检索：

1. 把历史交互压缩、提炼、结构化存储
2. 新问题到来时，语义检索相关记忆注入 prompt
3. 也可把记忆包装成工具，让 LLM 自主决定何时读写记忆

## 多 Agent 架构

1. 集中式（Controller-Agents）：中央控制器协调所有 Agent，适合任务分解明确的场景
2. 去中心式（Peer-to-Peer）：Agent 之间直接通信，无单一控制点，更灵活，适合动态协作
3. 分层式（Hierarchical）：管理 Agent → 协调层 → 执行层，适合企业级应用

## 编排

多 Agent 系统的核心是设计高效的协作机制，而不是简单堆叠多个 LLM 调用。主流编排框架（如 LangGraph / LangChain）基于有向图（状态机）定义工作流，天然支持循环、分支、条件跳转。

## 编排模式

- 顺序编排：Agent 按固定顺序执行
- 并行编排：多个 Agent 同时执行
- 条件分支 / 循环：根据中间结果决定下一步
- 竞争 / 评审：多个 Agent 产出后由评审者择优
