# RAG 混合检索与重排序

单一检索方式各有短板，混合使用可以互补，这是 RAG 检索优化的进阶手段。

## 为什么需要混合检索

关键字检索（稀疏检索）：

- 优点：精确匹配专有名词、产品名、缩写、编号，速度快
- 缺点：对同义词、拼写错误、语义改写不敏感，容易漏召回

向量检索（稠密检索）：

- 优点：理解语义、跨字面匹配，容错拼写错误，支持跨语言
- 缺点：对专有名词、缩写、编号（如 gpt-3.5、RAG）这类精确匹配反而效果差

## 混合检索原理

混合检索 = 关键字检索 + 向量检索，再按权重融合为一个排序结果。

最常见做法是把稀疏检索（BM25）与稠密检索（embedding 相似度）的分数加权求和：

```
最终分数 = alpha × 向量分数 + (1 - alpha) × 关键字分数
```

alpha 取 0 到 1 之间的值：alpha=1 是纯向量检索，alpha=0 是纯关键字检索，通常取 0.5 做折中。

## 重排序（Reranking）

向量相似度高，不代表最相关。重排序用更精准的模型对初步检索结果做二次精排。

常见做法：先召回 top 20，再用交叉编码器（cross-encoder）对 (query, doc) 逐对打分，取 top 5。

## bi-encoder 与 cross-encoder 的区别

- bi-encoder（双编码器）：query 和 doc 分别独立编码，速度快，适合大规模召回
- cross-encoder（交叉编码器）：query 和 doc 拼在一起编码，慢但更准，适合精排

典型的「召回 + 精排」两段式：bi-encoder 海选，cross-encoder 决赛。

## 优化层级（递进式）

```
Level 0：基础向量检索（baseline）
  ↓ 混合检索（向量 + BM25）
Level 1：混合检索
  ↓ 查询改写 + 多查询检索
Level 2：查询改写
  ↓ 重排序
Level 3：重排序（Reranking）
  ↓ 上下文压缩 + 父文档检索
Level 4：上下文压缩
```

每往上一层，检索质量都有提升，但实现成本也相应增加。从混合检索 + 重排序入手是性价比最高的组合。
